## Root cause (confirmed 2026-07-25T23:23:00+08:00)
- Mechanism: Every FSR3 compute entry includes `Integration.glsl`, which unconditionally declares all 18 writable image uniforms. Iris passes that full declaration set to the NVIDIA OpenGL compiler for composite70, so the compiler rejects the stage before unused callback code can reduce the active resource set.
- Evidence: preprocessed `shaders/composite70.csh` contains 18 image declarations; the called PrepareInputs callbacks require only 6.
- Toggle proof: pre-patch preprocessing returned `18`; with the conditional-binding patch the same composite70 preprocessing returns `6`. The other FSR3 stages return `2, 1, 1, 4, 3, 3, 1`, all within the driver limit.
- Fix scope: `Integration.glsl` plus one pass-selection macro in each of 8 FSR3 compute entries.

### Shadesmith generation failure
- Command: `.\\scripts\\shadesmith.ps1`
- Output: `StringIndexOutOfBoundsException: Index 371442 out of bounds for length 371442` at `UnusedCleaner.kt:34`.
- Cause: `UpdateDepthExtents` contains one opening brace in each `#if/#else` comparison branch and one shared closing brace. GLSL preprocessing selects one branch, but Shadesmith scans raw braces and sees one unmatched opening brace.
- Fix: move the comparison body's single opening brace after `#endif`; preprocessed GLSL remains identical while raw source becomes balanced.
