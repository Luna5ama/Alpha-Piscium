# Vibris 专用 Minecraft 实例按需启动

需要实机的任务可以自行启动已停止的专用实例。先用 `vibris_get_status` 查目标工作树；运行中的实例沿用正常准入与队列。重启已运行的游戏或启动器须由用户明确要求。

## 当前配置

本机 MCP 连接 `127.0.0.1:50051`。PCL 的 `1.21.11-Vibris` 实例在其游戏目录的 `config/vibris/server.json` 中配置了启动入口，核对时为 `I:\PCL\1.21.11-Vibris.bat`。相邻的 `1.21.11-Manual` 是另一个实例。部署可能调整路径，以当前受信任的专用实例配置为准。现有 `vibris_restart` 通过已连接的 Core 排空作业并重启游戏，冷启动能力待交付。

## MCP 实现与验收

在 Vibris 的 MCP 侧提供明确的按需启动操作，游戏离线时也能使用。由本机部署持有目标实例和启动入口的配置。调用者只表达启动意图；启动脚本正文可能包含游戏登录信息，只需使用配置的路径。普通状态查询保持只读。

- 目标已连接时复用；目标正在启动或计划重启时等待同一实例。多个 MCP 客户端同时请求、超时后重试，都至多启动一次。单次连接失败时核对目标进程和启动状态。
- 启动后等待目标 Core 握手，用 AP 工作树的正常状态入口确认可用。超时、配置缺失或目标身份不明时返回可操作的原因，保留其他实例和现有作业。
- 交付包括 MCP 实现、部署配置和实际工具用法。用隔离测试覆盖并发、重复调用和失败；在专用实例自然停止时验证一次从 MCP 冷启动到 AP 状态查询成功，记录实测版本和仍待验证的部分。用交付后的实际操作更新本页。
