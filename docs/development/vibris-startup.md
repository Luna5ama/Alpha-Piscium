# 使用 Vibris 验证 Alpha Piscium

1. 用实际检出的绝对路径作为 `worktree_root` 调用 `vibris_get_status`，检查连接、队列和作业准入状态。实例在线时复用当前实例，等待同一实例的在途作业完成。
2. 需要实机且 Core 离线时，通过配置了启动入口的 bridge 调用 `vibris_ensure_runtime`，传入相同的工作树。返回 `STARTUP_PENDING` 时继续等待。身份无法确认或启动入口缺失时，保留进程并检查返回原因。重启运行中的游戏或启动器需要用户明确授权。
3. 再次调用 `vibris_get_status`，确认 `operational` 和 `can_accept_job`。记录实际加载的 pack 修订、场景、设置和受影响的 pass。

2026-11-21，配置好的专用实例从离线到就绪用时 17.516 秒。第二个客户端复用了同一个游戏进程。并发启动、超时重试和实例身份等 7 项测试通过。

2026-11-22，独立 WDDM 读回验证了专用游戏进程在空闲、执行真实 720p 作业、队列排空三个边界依次使用 Idle (0)、Realtime (5)、Idle (0)。CPU 调度类保持 Normal。有后台 GPU 负载时可以运行同场同配置的正反序配对，逐组记下背景负载和哨兵耗时。调度类读回只验证档位切换，有竞争时的计时稳定性需用重复配对判断。
